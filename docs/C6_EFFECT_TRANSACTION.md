# C6 — EffectTransaction and side-effect state machine

`@agent-world/effects` records the lifecycle of a real-world effect. The coordinator creates `preparing`, then moves to `prepared`, then **stores `dispatching` before** a caller invokes an external executor. The coordinator does not execute side effects itself. A production store must durably commit that dispatch boundary before the external call.

An executor report is not a commit. `reported_success` leaves the effect in `dispatching`. Only a policy-accepted `confirmed` Observation retrieved from the ObservationStore can move it to `committed`; an accepted `contradicted` Observation moves it to `failed`. Weak, stale, unknown or inconclusive evidence moves it to `unknown`. A timeout or executor exception after dispatch is `unknown`, not failure. A certified pre-start failure can be `failed`.

`failed` after an accepted contradiction means the expected postcondition is known not to hold at observation time; it does not prove the executor never ran or that no other side effect occurred. A weak or stale contradiction produces `unknown`. `unknown` is terminal in C6's state machine but means unresolved external reality, not business failure or success. Late callbacks and observations cannot change terminal C6 history. The package has no blind retry or redispatch API. C7 will add read-only reconciliation before deciding what happened. An idempotency key identifies a semantic effect; it is not permission to retry. The key is SHA-256 of canonical JSON containing task, intent, action, sorted canonical resources, parameters and executor identity. Timestamps and attempt metadata are excluded.

The effect records task, contract, intent, execution, executor, canonical resources, resource fencing tokens, grant and lease IDs, budget reservation IDs, policy decision and append-only observation IDs. C6 does not grant authority or settle budgets; especially, `unknown` does not release a reservation. The in-memory effect store and event sink are separate, so durable transactional state-and-event persistence remains future work. C6 is not integrated into M5.
