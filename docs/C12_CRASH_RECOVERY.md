# C12 Crash Recovery

`@agent-world/recovery` starts in `recovering` mode. The C11 commit gate rejects consequential work until recovery finishes and the host health checks allow `normal`. The M5 adapter runs this check at startup. Recovery emits journal events to the existing JSONL event path; journal records describe actions taken and are never authority or permission to dispatch.

RecoveryPlanner classifies the current effect and budget stores. An orphan reservation created before its effect is cleaned only when the effect store is declared healthy and no effect exists. `preparing` and `prepared` effects fail with certified nonstart and release their holds. Neither is dispatched. A `dispatching` effect is ambiguous after a crash. If a persisted, correctly bound and policy-accepted observation confirms its postcondition, recovery may finish C6 settlement and budget accounting locally. Otherwise it becomes `UNKNOWN`, retains its budget hold and gets one deduplicated C7 reconciliation job. Existing `UNKNOWN` effects also get a job. Recovery never invokes an executor, planner or inference provider.

A `committed` effect remains committed. If its reservation is still active, recovery commits the recorded actual amount idempotently. Missing or invalid accounting evidence leaves the runtime read only and preserves the hold. A failed effect remains historical; a hold is released only when nonstart was certified. Recovery rereads the stores before applying a supplied plan and refuses an incomplete or stale plan. It does not issue, renew or restore leases or grants. Emergency stop and quarantine are not cleared. The host checks current authority readability and runs a Supervisor startup sweep before normal mode.

The deterministic tests cover crashes before reservation, after reservation, while preparing or prepared, after dispatch started, with an unknown outcome, after an observation was stored, after effect settlement, and after budget settlement. They cover duplicate recovery, missing receipts, expired holds, emergency stop, unreadable authority, and incomplete plans.

## Persistence limit

Current C1–C10 effect, budget, observation, history, lineage, emergency-stop and quarantine stores are in memory. The JSONL runtime event path records provenance and replay events but does not reconstruct these control-plane projections after a real process restart. Thus C12 defines and tests recovery semantics over injected stores; the M5 adapter recovers only the state available in its current process. It does **not** provide production process-crash durability or guarantee that C8 history, C9 lineage, emergency stop or quarantine survive a restart. Durable transactional stores and projection rebuild are future hardening work. A production host must declare its critical stores healthy only after it has loaded and validated durable facts.
